## Системы, которые следует покрыть трейсингом

### InternetShop ↔ ShopAPI ↔ ShopDB & CRMA ↔ CRMAPI ↔ ShopDB

- Это критическое место, так как заказы могут потеряться, если транзакция не будет правильно зафиксирована в БД.

### MES ↔ MESAPI ↔ MESDB

- Трейсинг должен охватывать передачу данных о заказах между этими компонентами, чтобы обнаружить проблемы, такие как задержки или сбои в обработке.

### CRMAPI ↔ MessagesQueue ↔ MESAPI

- Трейсинг должен отслеживать количество сообщений, время их обработки и успешность доставки.

## 3DFileStorage ↔ ShopAPI ↔ CRMAPI ↔ MESAPI

- Работа с 3D-моделями требует передачи данных между хранилищем файлов и другими компонентами. Потери данных или задержки могут произойти, если система не отслеживает эти операции.

## Cписок данных, которые должны попадать в трейсинг

- Идентификатор заказа (Order ID). Позволяет отслеживать путь конкретного заказа через систему.
- Идентификатор пользователя (User ID). Помогает отслеживать действия конкретного пользователя, такие как создание заказа или загрузка 3D-модели.
- Таймстампы. Помогают анализировать задержки и определить, на каком этапе происходит сбой.
- Состояние заказа (Order Status). Позволяет отслеживать, на каком статусе заказ "завис".
- Ошибки API. Позволяет отслеживать ошибки на уровне API и обнаружить сбои на ранних стадиях.
- Задержки в сообщениях RabbitMQ. Время, которое сообщение проводит в очереди RabbitMQ.

## «Мотивация»

Трейсинг — это важный инструмент для отслеживания пути каждого заказа или события через систему. Внедрение трейсинга в архитектуру системы ювелирного магазина Александрит обеспечит компанию важными данными о производительности, задержках и возможных сбоях. Трейсинг позволяет отслеживать все ключевые шаги в процессе обработки заказа и его передачу через различные компоненты системы, что дает несколько значительных преимуществ:

### Повышение надежности системы

- Трейсинг поможет выявить узкие места, на которых заказы могут зависать, такие как задержки в RabbitMQ, проблемы с обработкой запросов в API или долгие вычисления в MES. Это позволит оперативно выявлять и устранять проблемы до того, как они повлияют на пользователей и заказчиков.

### Улучшение производительности

- Трейсинг даст полную картину времени обработки заказа на всех этапах. С помощью собранных данных можно выявить задержки и оптимизировать работу системы, например, через добавление новых серверов или оптимизацию кода.

### Снижение количества ошибок и возвратов

- Когда система отслеживает каждое действие заказа, можно обнаружить ошибки и сбои на ранних этапах, минимизируя возможность потери данных или неправильной обработки. Это снижает вероятность возвратов и негативных отзывов от клиентов.

### Обеспечение прозрачности процессов

- Трейсинг позволит не только техническим специалистам, но и менеджерам бизнеса отслеживать статус заказов и видеть реальные показатели производительности. Это поможет улучшить коммуникацию между командами и повысить эффективность.

## Технические и бизнес-метрики, на которые повлияет внедрение трейсинга

### Время обработки заказа (Order Processing Time)

- Это критическая метрика для бизнеса, так как она напрямую влияет на удовлетворенность клиентов. С помощью трейсинга можно точно определить, на каком этапе возникают задержки, и устранить их.

### Время отклика API (API Response Time)

- Меньше задержек в API — более быстрый отклик системы, что улучшает опыт пользователей и повышает конверсию. Трейсинг поможет точно выяснить, какие части API требуют улучшений.

### Процент успешных и неуспешных операций (Success/Error Rate)

- Это поможет быстро выявлять проблемы в системе, такие как ошибки в запросах или неудачные транзакции. Это особенно важно для поддержания бесперебойной работы сервиса и удовлетворенности клиентов.

### Пропускная способность сообщений в RabbitMQ (Message Throughput)

- Помогает анализировать, может ли система обрабатывать возросший трафик, и позволяет предсказывать будущие перегрузки, добавляя новые потребители или увеличивая мощности системы.

### Продуктивность операторов MES (MES Operator Efficiency)

- Это важная метрика для повышения эффективности работы операторов. Трейсинг поможет понять, где именно теряется время, и оптимизировать рабочие процессы.

## Предлагаемое решение

Для эффективного мониторинга работы системы и трассировки запросов (трейсинга) предлагается использовать распределенный трейсинг на основе OpenTelemetry и Jaeger. Эти технологии помогут отслеживать каждый шаг обработки заказа, выявлять задержки, сбои и повышать прозрачность работы системы.

- [Ссылка на диаграму контейнеров С4](https://drive.google.com/file/d/1C-acCw46Cz6FDgNDMQQfZFpl2Rs0vrXT/view?usp=drive_link)

### ✅ Технологии:

- OpenTelemetry – стандарт для сбора и передачи данных о трейсинге.
- Jaeger – хранилище и визуализация трассировки запросов.
- Prometheus (для сбора метрик) и Grafana (для визуализации трейсинга).
- Elasticsearch (ELK) – для логирования и хранения трейсинговых данных.

### 🔧 Необходимые доработки и новые компоненты

- 🎯 Внедрение OpenTelemetry SDK в API (Shop API, CRM API, MES API). Нужно добавить клиент OpenTelemetry в код API-сервисов.
- 🎯 Добавление OpenTelemetry в RabbitMQ. Нужно включить мониторинг сообщений в RabbitMQ.
- 🎯 Развертывание Jaeger для хранения и визуализации трейсинга. Даст возможность хранить и анализировать трассировку запросов.
- 🎯 Добавление трассировки базы данных (ShopDB, MESDB). Даст возможность анализировать время выполнения SQL-запросов.
- 🎯 Логирование ошибок и связка с ELK (Elasticsearch + Logstash + Kibana). Даст возможность хранить логи ошибок и связывать их с трейсингом.

## Компромиссы

Для компании Александрит внедрение трейсинга может не принести пользы или быть нецелесообразным в следующих ситуациях:

### Проприетарная система MES

- MES (Manufacturing Execution System) — это проприетарная система, которая уже была закуплена с исходным кодом, и её интеграция с OpenTelemetry или другими инструментами трейсинга может потребовать значительных доработок.
- ✅ Альтернатива: Временно ограничить трейсинг на уровне MES, сосредоточив внимание на других частях системы, где проще внедрить трейсинг, например, API и базы данных.

### Сложности с инструментами для работы с очередями (RabbitMQ)

- Внедрение трейсинга для RabbitMQ — это непростая задача. На практике будет сложно интегрировать OpenTelemetry с очередями сообщений без значительных доработок.
- ✅ Вместо полного трейсинга сообщений можно сосредоточиться на мониторинге метрик RabbitMQ, таких как количество сообщений в очереди, количество ошибок и задержки.

## Меры безопасности для системы трейсинга

1. 📌 Для доступа к данным трейсинга внутри компании внедрить аутентификацию. Все сотрудники компании, имеющие доступ к данным трейсинга, должны проходить аутентификацию через корпоративную систему. Для этого будет использована OAuth 2.0 или OpenID Connect для единой аутентификации через корпоративный Identity Provider (например, с использованием Active Directory или LDAP).
2. 📌 Для защиты конфиденциальности данных в трейсинге внедрить шифрование данных. Все данные, передаваемые между компонентами системы (например, между OpenTelemetry Collector и Jaeger, или между сервисами), должны быть зашифрованы с использованием TLS/SSL. Это гарантирует, что данные не будут перехвачены и прочитаны третьими лицами при передаче по сети.
3. 📌 Для отслеживания и защиты от несанкционированного доступа внедрить логирование доступа. Все попытки доступа к данным трейсинга должны быть записаны в системах логирования, таких как ELK (Elasticsearch, Logstash, Kibana). Это включает попытки входа в систему, создание или изменение настроек и доступ к данным, связанным с трейсингом.
4. 📌 Для защиты от внешних атак на систему трейсинга внедрить ограничение внешнего доступа. Доступ к данным трейсинга из внешних систем должен быть строго ограничен. Все внешние пользователи и системы, такие как API-партнеры, должны получать доступ к данным через API Gateway, который будет выполнять дополнительные проверки на безопасность.
